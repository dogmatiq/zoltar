# zoltar step 1: observations

Collected while the step 1 workflow runs. To go through after it finishes.

## From James

1. **`isStandardLibrary` feels like a hack.** It guesses (no dot in the
   import path, plus a directory in the local GOROOT), so the answer depends
   on the machine. Proposed: replace it with a checked-in list of standard
   library package paths generated by `go list std`, recorded with the Go
   version it came from. The census (step 5) generates the same list, so it
   carries over.

2. **Don't refer to "zoltar" in API docs.** Doc comments describe what the
   code does ("the predictor doesn't check assumptions", "assumptions aren't
   checked"), not the project. The README and the package doc's opening line
   may still name it. Applies to the design doc's proposed comments too
   ("Zoltar doesn't check assumptions", "zoltar never tries..."). Follow-up
   pass after the workflow; slice 4 was already scripted.

3. **`Const` should be generic.** Agreed shape:
   - `Const[T predeclared](v T)`: static type is the matching predeclared
     type (no `~`: named types in the analyzer aren't the program's).
   - `ConstAs[T ~predeclared](t types.Type, v T)`: a constant of program
     type `t`, including named types such as `time.Month`; panics if `t`'s
     underlying kind differs or `v` doesn't fit. Pairs with `As[T]`.
   - `Zero(t types.Type)`: reflect-style zero value; replaces `Const(t, nil)`.
   Callers no longer need `go/constant`.

4. **`append` aliasing.** Confirmed wrong predictions in 3 of 4 cases
   (spike in scratchpad/spike/budgetcheck/append_spike_test.go). Decided:
   track capacity (known with room: reuse; known full: copy; unknown: might
   reuse, as conditional writes). Don't compute growth. Now part of step 2
   (Soundness); later steps renumbered (identity 3, maps 4, census 5).

5. **"Never wrong" is currently false.** Audit done: about 320 programs,
   30 wrong predictions from nine causes (init-created closures, goroutines
   started by returned callees, later callbacks from skipped code, addresses
   escaped to skipped code during init, results of read-only calls sharing
   with arguments, unsafe, zero-size pointer equality, out-of-range
   float-to-int, fused multiply-add) plus `append`. Design doc step 2 is now
   "Soundness" covering all of them; `ReadOnly`'s doc now says its result
   may share memory with its arguments. To do after the workflow:
   - move the audit programs and harness into the repo as step 2's
     acceptance tests (they live only in the scratchpad now:
     `scratchpad/audit/` and `scratchpad/spike/budgetcheck/audit*_test.go`);
   - say in README and doc.go that the promise has known exceptions until
     step 2 lands.

6. **`ComputedBy` is limited to single-result functions** only because
   `compute` returns one `constant.Value`. Rules out `strconv.Atoi`,
   `strconv.ParseBool`, `strings.Cut`, `utf8.DecodeRuneInString`. Agreed
   shape: `compute func(args []constant.Value) []constant.Value`, one entry
   per result, each independently: nil = that result's zero value;
   `constant.MakeUnknown()` = unknown; anything else = exact. Returning a nil
   slice means "can't compute": every result unknown (so no `ok` return).
   `Atoi("abc")` gives exactly `0` plus an unknown error. A length mismatch
   panics at the call. An unknown result still carries its static type from
   the signature, and its dynamic type when that isn't an interface
   (automatic; `compute` says nothing). Gap left open: saying "not nil" and
   "dynamic type X" for interface results (e.g. `*strconv.NumError`) needs a
   richer return than `constant.Value` and access to the program's types;
   design it together with `ReturnsNew` for interface results (slice-report
   item 1). Census adapters use the same shape.

7. **Budget and cancellation (provisional).** Reverses "remove the budget,
   add nothing": the review found a fan-out program taking minutes (it
   genuinely makes 2^n distinct calls) plus a quadratic memo lookup
   (call.go:597, fix with a hash). Provisional decision: no built-in limit;
   `Predict(ctx, fn, args)` with the prediction carrying ctx (like
   http.Request); callers check `ctx.Err()` afterwards; cut-short values get
   a `Cancelled` blind spot and are never cached; the predictor stays usable;
   performance regression tests on realistic code; an opt-in local
   precision limit (`WithCallLimit`) only if a consumer asks. James: "reasonable,
   but not ideal". Alternatives to revisit: `ValueOf` returning an error;
   `p.Err()` scoped to the prediction; eager values so only `ValueOf` does
   work (spike running: does eager cost too much on real programs?).

## Decisions after step 1 (recorded in design.md)

- **Go 1.27 / x/tools in go.mod:** fine; zoltar moves to its own repo before
  tagging.
- **`ReturnsNew` for interface results:** a new pointer with unknown dynamic
  type (not nil, distinct per call). Step 2.
- **`ComputedBy(fn any)`:** pass the real Go function; zoltar converts
  constants and complete constant slices in and out via reflect; nil error =
  zero value, non-nil = new pointer of unknown type; panics = unknown.
  Supersedes observation 6's `compute` shape. Census becomes a plain table.
- **Placeholders compared by identity:** accepted.
- **Recursion:** followed while all arguments are exactly known, with a
  higher depth limit for that case (`Limit` if exceeded); unknown arguments
  not followed (`Unsupported`). Step 2.
- **`As[T]`: strict by kind** (same basic type underneath, as reflect.Kind):
  `As[int]` accepts int, time.Month, myapp.Level; not int64 or float64.
  `ConstAs` uses the same rule. Follow-up pass.
- **`ComputedBy` and slices: stay fully sound.** Until capacity is tracked
  (step 2), calls whose slice arguments have unknown capacity aren't
  computed; the call's own variadic slice is fine. Step 2 lifts it: pass
  real capacity, detect result sharing and argument writes by observation.
  No options on `ComputedBy`.
- **Representation:** using `go/constant` for run-time values was a mistake.
  Step 2: known values become real Go values of the right size, with Go's
  own arithmetic (exact -0, NaN, infinities). Negative zero is a known
  exception until then.
- **Eager values: viable.** Spike: 0-3.2x extra on five real codebases, at
  most +285 ms per program, no change to retained memory. Supports making
  value methods lookups only, so only the question does work and needs a
  context.
- **`ComputedBy` no longer implies `Pure`** (done). A call that isn't
  computed may modify anything reachable from its arguments unless another
  assumption says otherwise; write `ComputedBy(fn), Pure` for functions that
  write nothing. Computed calls will have their writes observed (step 2).
- **New repo `dogmatiq/zoltar`** (created via dogmatiq/repos#55, merged):
  only the finalized public API goes in first, as an API-only design with no
  implementation. Nothing goes in until the API is locked. The
  implementation stays in the enginekit `zoltar` worktree until then.
  (`make precommit` there also runs `go fix`, which modernizes loops to Go
  1.27 iterator methods; expect that when the implementation moves.)
- **API review, 2026-10-31** (all in design.md): `Const`/`ConstAs` ->
  `Known`/`KnownAs`; `Iteration` -> `Prediction.Loops()` and `Loop`
  (`Header`, `Contains`, `Passes`, `Pass`); removed `BlocksFrom`,
  `AlwaysLeadsTo`, `Depth`, `Prediction.Predictor`, `Predictor.Program`,
  `IsRecursive`; `Target` opaque with `Func()`/`Args()`; `BlindSpot`
  implements `error`; `Target.IsFollowed` considered and rejected
  (staticconfig walks by whether a package imports Dogma instead).
- **Cost (re-measured and profiled):** three of five real codebases still
  didn't finish. Not many calls: repeated work (unshared nested reads,
  unknowns piling up, caching off inside cycles) plus exponential re-solving
  of calls inside loops. Prototypes fix most; the loop pattern needs a rule.
  New step 1b "Performance" in design.md.
- **Cancellation: decided.** Values and control flow are eager. `ctx` and an
  error on calls that make predictions (`Predict`, `Follow`, `FollowAll`,
  `Pass`, `Func.Predict`) and that ask for values (`ValueOf`, `Returns`,
  `Targets`); everything else is a lookup. A fixed internal work limit,
  counted in work units with cached results charging their original cost,
  gives deterministic `Limit` blind spots. No `Cancelled` blind spot.
- **Still open:**
  - (`ForEachInstruction`: removed.)
  - the memo treats unknown arguments as equal whatever their reason (the
    profiling also found entries that can never match; fixed in step 1b).
  - `TestSoundness` under `-short`: skip it? (adds ~4s)

## From the slice reports

1. **`ReturnsNew` on functions returning an interface** (such as
   `errors.New`) gives an unknown result: the internal values can't express
   "not nil, dynamic type unknown". Settle before step 5 (census) adds such entries.
2. **`ComputedBy` and slice arguments.** `constant.Value` can't hold a
   slice, so only variadic arguments are passed, one constant each.
   `strings.Join(parts, "-")` can't be computed. Needs a design decision
   before step 5 (census).
3. **`Equal` with several timelines** is always false, even when both sets
   look the same. Sound, but the design doc should say so.
4. **Design doc contradiction about `Opaque`.** The mechanism section says
   there's no user option for it; the API exports it (as agreed, as an
   escape hatch). Fix the wording.
5. **System `gofmt` is Go 1.26** and can't parse generic methods; the Go 1.27
   `gofmt` is clean. Affects any tool using the PATH `gofmt`.
